No global installation was performed. Dashmotion's layout script generated the standalone `hardware.html`; its structural checker passed that diagram. The integrated continuous execution model uses native layout so labels can wrap, plus a single current-transfer overlay. Technical correctness is grounded in the sources below, rather than inferred from a design skill.

## Precision and hardware assumptions

- One discrete NVIDIA GPU. Parameters fit in GPU DRAM. No offloading, distributed inference or prefix caching.
- A Llama-style pre-norm decoder with RoPE, GQA and SwiGLU. The example uses 32 query heads, 8 KV heads, a head dimension of 128 and model width 4096. FFN width is model-dependent.
- Prefill starts with T = 8 and S = 0. Decode starts with T = 1 and S = 8. Decode's input ID and existing cache are explicit initial conditions supplied by a previous forward; they are not generated by loading model parameters.
- FP16 activation and residual boundaries are a reference choice. Floating-point GEMM accumulates in FP32 here. Integer GEMM uses INT8 operands and INT32 accumulation. Norm / softmax statistics use FP32.
- W4A16 stores packed INT4 weights and reconstructs FP16 working tiles. W8A8 uses INT8 GEMM; KV8 is a separate selected choice. The QServe path illustrates W4 storage, W4-to-W8 progressive reconstruction, INT8 GEMM and KV4; it does not implement the full QoQ / SmoothAttention algorithms.
- Embedding, norm parameters and LM head remain FP16. A8 does not imply integer residuals, query tensors, nonlinearities or softmax.
- Quantized KV is converted to FP16 working tiles for this floating-point attention example. The stored cache remains compressed. Query is not appended to KV.
- L2 is shared outside the SM. Shared Memory and Registers are on the SM. L1, cache eviction and physical register allocation are abstracted.
- Global loads follow an illustrative L2 miss / fill path. L2 hits and alternative kernel staging are possible. Shared-memory staging is explicitly an example, not mandatory for every kernel.
- The view shows logical buffer copies, working tiles and dependencies. A load preserves its source; a dtype conversion changes a working representation; a compute action can create a new derived tensor. Compute units are not storage buffers.
- The reference execution materializes FP16 activation boundaries. Fusion may omit these stores. Attention scores and probabilities remain on-chip as logical tiles, rather than full DRAM matrices.
- QK, Softmax and PV are separated to expose their dependencies. A real fused attention kernel interleaves tiles and online statistics, rather than executing three full-matrix passes in this order. Attention execution-unit mapping is kernel-dependent.
- The remaining layer stack is an explicitly collapsed stage. Every layer has distinct parameters and its own K/V cache.
- Metadata badges denote format-dependent scales / zero-points, not one asserted numeric dtype. Metadata adds to payload memory.

## Continuous state presentation

Every operator has a Start frame, individual actions and an End frame. Consecutive frames share an explicit immutable snapshot history. An operator's End snapshot is the exact same snapshot used by the next operator's Start. Live buffers never reset because the selected operator changes.

The default diagram shows one current transfer arrow. Before / After controls inspect the same action on either side of its state transition. The state-change table lists added, updated and released copies. Full tensor labels wrap instead of being truncated. Clicking a tensor opens its copies, dtypes, parent tensors and lifecycle; each entry navigates to the corresponding action.

Weights remain resident and unchanged during runtime. Temporary operand / accumulator copies are explicitly released. Residual buffers remain live through their corresponding residual adds. KV appends occur only in the selected layer's append stage or the explicitly collapsed remaining-layer stage.

## Numerical experiment and memory calculator

The symmetric quantizer uses z = 0 and q in [-qmax, qmax], with round-to-nearest, ties-to-even. The INT4 experiment uses 15 signed values [-7, 7], leaving one of the 16 encodings unused. This convention is not a claim about every INT4 format. The experiment runs JavaScript floating-point arithmetic and does not emulate FP16 scale rounding or Tensor Core instructions.

Weight payload = Pq × Wbits / 8.

KV payload = 2 × B × L × S × Hkv × d × KVbits / 8.

Pq counts quantized linear parameters, not all model parameters. GQA uses KV-head count Hkv. Additional parameters, metadata, workspace, activations, padding, allocator state and high-precision KV residual buffers are excluded from payload totals. Capacity ratios do not predict speedup.

## Verification scope

The source includes numerical checks and continuous-state invariants for all four precision configurations in both phases. These verify boundary identity, read-source availability, persistent weights, residual lifetime, KV append length / dtype, integer and floating-point GEMM operands, on-chip attention handoff, metadata and tensor-history navigation.
