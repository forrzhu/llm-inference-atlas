一次反量化，处理多大？

优化 kernel 通常每次处理一个 tile。压缩权重驻留显存；当前 tile 在片上恢复成计算所需的格式。寄存器、shared memory 的槽位随 kernel 迭代复用。下一 token 又会用到权重，可能重新从显存读取；不需要每次从 SSD 加载整个模型。

INT8 × INT8，为什么还要乘 scale？

两个向量分别用一个 scale；先累加整数乘积，再恢复量纲。这个实验的误差来自量化。

少了多少数据？算一笔显存账

比较 FP16 与所选方案的权重、KV 理论 payload。容量估算不等于实测延迟，也不代表完整峰值显存。

payload 之外还有什么？

量化 scale、zero point、对齐与 padding；embedding、LM head、norm 等保留高精度的权重；激活、临时 workspace、分配器、CUDA graph 和可能的 KV 高精度 residual buffer。这里不把它们合成一个虚构的“模型峰值显存”。

教学示例：若每 128 个 W4 权重额外保存一个 2-byte scale，7B 权重还需约 104 MiB scale。真实格式可能还有 zero point 或两级参数；QServe 使用自己的元数据布局。

本演示的边界

单个离散 NVIDIA GPU；权重放得下 GPU DRAM；无 offload / 分布式 / prefix cache。采用 Llama 风格 pre-norm、RoPE、SwiGLU 与 GQA。边界激活默认 FP16；示例的 norm/softmax 归约与浮点 GEMM 累加用 FP32。具体融合、舍入、缓存路径与中间 dtype 会随 GPU、kernel 和框架变化。
