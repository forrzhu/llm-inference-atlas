Tile-level Dequantization

Optimized kernels typically load weight tiles and perform the required dtype conversions on-chip. GPU DRAM retains the compressed format. Temporary Registers and Shared Memory are reused as the kernel iterates. A later token may read weights again without reloading the checkpoint from SSD.

Symmetric Uniform Quantization

Adjust the bit-width and clipping range to inspect quantized values, reconstruction and error. This numerical model does not execute an LLM.

Reference quantizer: z = 0, q ∈ [−qmax, qmax], round-to-nearest, ties-to-even. The INT4 example uses [−7, 7]: 15 values out of 16 possible bit patterns. Other quantizers may use [−8, 7], asymmetric quantization or a non-uniform codebook.

Additional Runtime Memory

Additional memory includes quantization scales, zero-points, alignment, padding, high-precision embedding / LM-head / norm parameters, activations, workspace, allocator state, CUDA graphs and any high-precision KV residual buffer.

Example: one 2-byte scale per 128 W4 values adds about 104 MiB for 7 billion values. Real formats may also require zero-points or progressive-quantization parameters.

Model Assumptions

One discrete NVIDIA GPU; the model fits in GPU DRAM. No offloading, distributed inference or prefix caching. Llama-style pre-norm, RoPE, SwiGLU and GQA. Activation / residual boundaries are FP16. Norm / softmax reductions and floating-point GEMM accumulators use FP32 in this reference path.

L2 is outside the SM; Shared Memory and Registers are inside it. Shared-memory staging and attention execution-unit mapping depend on the kernel. The hardware model is a logical reference, not a profiler trace or chip floorplan. The remaining layer stack is an explicitly collapsed stage.

Checkpoint conversion is illustrated as offline CPU preparation and can also run on a GPU. Sources checked: October 26, 2026.
